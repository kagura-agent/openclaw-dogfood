# 使用观察 — 2026-08-06

## 过去 24h 的 cron / channel 使用

| 场景 | 观察 | 结论 |
|---|---|---|
| Discord cron delivery | `workloop-night`、`github-patrol`、`cove-patrol`、`channel-patrol`、`study-loop`、`auto-trader` 和 `community-ops` 均产出可见频道摘要。 | **顺畅**：isolated cron → Discord delivery 持续可用。 |
| FlowForge 工作流 | `workloop-night` 使用 PR snapshot 去重；相同快照直接完成，变化时才进行有限复核。 | **顺畅**：持久工作流和显式去重抑制了无意义的重复外部操作。 |
| Channel patrol | 能汇总 finance、study、Cove、GitHub inbox、ABTI 等跨频道状态，并把共同阻塞点关联起来。 | **顺畅**：跨频道可观测性强，避免在孤立 cron 中重复处理同一问题。 |
| 安全门禁 | `auto-trader` 在市场未开盘时只生成待执行建议，未执行交易；finance skill 的 Token 配置也明确要求私下处理。 | **顺畅且正确**：时间/授权/隐私边界被保留。 |
| 原生 Codex 代码任务 | `cove#510` 的冲突与语义反馈只能在其原生 Codex task thread 中处理；isolated cron 正确停止而不是换 harness 或手写代码。 | **正确但有摩擦**：执行权限/入口与定时巡检的上下文不连续。 |
| 定时任务失败可诊断性 | OpenCode `close-prs` 遇到 upstream-comment 403，ABTI follow-up 失败/超时；它们被如实汇入既有待办，而非伪装成功。 | **正确但有摩擦**：cron 摘要存在，但需更容易获取原始 run history、错误与重试证据。 |

## 值得保留的做法
- **以证据和去重决定是否行动**：夜间 workloop 用 `repository#number:updatedAt` 快照；没有变化不再制造外部噪声。
- **让失败显式可见**：403、超时、冲突和缺少原生 task runtime 都被记录为阻塞，不用猜测性 workaround 覆盖。
- **跨频道统一阻塞项**：Cove #510 同时出现在 contribution 与 review 视图中，已明确应回到同一个原生 Codex task thread 处理。
