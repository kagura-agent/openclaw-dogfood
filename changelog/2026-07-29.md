## 新发现：v2026.7.2-beta.5 发布

昨日（07-28）发布了 beta.5，打破了连续 4 天的静默期。完整 changelog 为累积式（覆盖整个 7.2 周期 3908 PRs），以下是与我们最相关的变化：

---

### 🆕 对我们有用的新功能（可立即采用）

1. **Claude Opus 5 支持** — 已加入 catalog 和 runtime。我们当前用 Opus 4.6，可评估升级路径，尤其是复杂推理任务。

2. **Session rewind & branching** — 可从任意消息 rewind/fork 对话，跨 web 和 native apps 切换分支。对调试长对话和探索不同路径非常有用。

3. **Fast active-memory recall** — 默认启用跨对话记忆回溯。我们的 memory_search 使用频率高，这个改进直接加速日常 recall。

4. **Per-job dynamic cadence** — cron 支持动态调节频率。我们的 12+ cron jobs 可以根据条件动态调整执行间隔，减少无效运行。

5. **`/loop` 命令** — 新增循环执行 scheduling 命令。适合快速设置重复性短任务。

6. **Guided memory imports** — 支持从 Claude Code/Codex/Hermes 导入 memory。方便统一管理跨工具的知识积累。

### 🔧 修复了我们遇到过的痛点

7. **CJK 文本 compaction 估算修复** (#114386) — 之前 compaction 对中日文文本长度估算不准，导致压缩时机不当。我们大量使用中文，这直接改善会话管理。

8. **Cron one-shot 和 startup catch-up 恢复** (#107236, #110351) — 修复了 one-shot jobs 丢失和重启后 catch-up 不执行的问题。我们之前遇到过 restart 后 cron 漏执行。

9. **Cron job state 跨重启保持** (#111292) — script state 和 scheduled authority 在 restart 后正确保持。减少我们维护时的状态丢失焦虑。

10. **Discord/iMessage/WhatsApp delivery 跨 crash 保持** (#110274, #110409) — 我们主要在 Discord，这确保消息不再因 crash/restart 丢失。

11. **Feishu outbound delivery 修复** (#113152) — 我们有 Feishu 集成场景，这修复了发送失败的问题。

### ⚡ 值得关注但暂不采用的

12. **Interactive MCP Apps & dashboards** — 可在 channel 中打开 ticketed MCP Apps 并 pin 到 dashboard。场景强大但需要先设计 MCP App。

13. **State quarantine store** — 数据安全兜底：主数据库损坏时 quarantine store 存活。适合生产级部署，我们暂无需要但值得了解。

14. **Meetings: Teams/Zoom/Meet 插件** — 自动加入会议并收集 durable transcript。如果未来有会议场景可评估。

15. **Kimi K3 模型支持** — 新模型选项，可在特定场景测试。
