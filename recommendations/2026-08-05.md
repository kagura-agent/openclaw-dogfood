# 采用建议 — 2026-08-05

## 1. 在下一次官方插件变更前升级到 `2026.7.1-2`
**优先级：中｜风险：低**

- **场景**：我们依赖多种 OpenClaw 官方/受跟踪插件，且历史上出现过 plugin 安装与兼容性问题。
- **建议**：不为这一个 hotfix 紧急变更生产环境；下一次需安装/更新官方插件或与下一稳定版合并时，先升级到 `2026.7.1-2` 以上。
- **验收**：核验版本；执行非破坏性的 plugin 查询/更新预演；确认 plugin skills discovery、Discord cron delivery 与 `openclaw doctor` 没有回归。
- **收益**：避免新版 npm metadata 格式导致 correction release 无法安装的失败路径。

## 2. 让“等待人工安装 skill”的 cron 自动降频
**优先级：高｜风险：低**

- **场景**：auto-trader 因 `trade_plan_builder_skill` 未安装而正确停止，但在用户选择安装范围前会重复提醒。
- **建议**：给此类 cron 加 trigger/状态门：首次阻塞后记录等待状态；在收到安装范围选择或检测到 skill 已安装前，降低频率或静默。
- **收益**：保留执行门禁，同时减少重复 Discord 投递和 token 空耗。

## 3. 优先修复 Cove task 的可执行状态回写
**优先级：高｜风险：中**

- **场景**：task preamble 要求 agent 开工/完成时更新状态，但 Cove session 中可用工具被 policy 过滤，导致 heartbeat 只能说 `HEARTBEAT_OK`。
- **建议**：对照 Discord channel 的 tool/skill 注入，先做最小验证：Cove session 是否能发现并调用 task-update；再修 plugin capability 描述或 policy 映射，最后用真实 task 验收 `in_progress → in_review`。
- **收益**：让 task 工作流从“要求”变成可验证的闭环，减少人工追踪。

## 暂不采用
- **立即升级仅为新功能**：`2026.7.1-2` 没有功能新增，不值得为它打断稳定运行的 cron。
- **为解决 cron schema 错误盲目改 payload**：当前只看到上一轮的笼统 provider 错误；应先保留原始失败 payload/trace，再做最小复现。
