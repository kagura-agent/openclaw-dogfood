# 采用建议 — 2026-07-31

## 基于 v2026.7.2-beta.5 changelog 的采用建议

### 🔴 高优先级 — 升级后立即采用

#### 1. CJK Compaction 修复验证
- **背景**: #114386 修复了 CJK 文本在 compaction 估算中的计算错误
- **我们的痛点**: 中文消息偶尔 compaction 异常，导致上下文窗口利用不充分
- **行动**: 升级后第一时间用大量中文对话测试 compaction 行为
- **验证方法**: 对比升级前后相同长度中文对话的 token 使用情况

#### 2. Cron 可靠性增强
- **背景**: 多个 PR 修复了 one-shot catch-up、script state 跨重启保留、慢批次阻塞等问题
- **我们的使用**: cron 是我们日常运营的核心（version-check、heartbeat 等）
- **行动**: 升级后观察一周 cron 行为，特别关注 gateway 重启后的 catch-up
- **新功能**: per-job dynamic cadence 和 gated script payloads 可以优化我们的调度策略

#### 3. Durable Channel Delivery
- **背景**: Discord/Telegram 等渠道消息在 gateway 重启后可恢复
- **行动**: 升级后进行一次 gateway 重启测试，验证消息不丢失

### 🟡 中优先级 — 近期值得探索

#### 4. `/loop` 命令
- **是什么**: 交互式循环命令，替代手动重复操作
- **场景**: 可能替代部分 cron 场景，适合短期循环任务（如批量处理）
- **行动**: 升级后试用 `/loop`，评估是否适合某些工作流

#### 5. Session Rewind & Branching
- **是什么**: 从任意消息点回溯/分叉对话
- **场景**: 调试长对话时回退错误决策，在关键节点创建分支测试不同策略
- **行动**: 了解 API/CLI 接口，评估集成到工作流的可能性

#### 6. Scheduling: Dynamic Cadence
- **是什么**: cron job 可以根据运行结果自动调整频率
- **场景**: version-check 在有新版本时加密检查频率，无新版本时降低
- **行动**: 了解 trigger script 语法，为 version-check job 设计动态调度策略

### 🟢 低优先级 — 持续关注

#### 7. Interactive MCP Apps
- 潜力大但我们还没有明确的 MCP App 需求，待业务场景成熟后再采用

#### 8. Structured Questions & Approvals
- option cards 和 push notification approvals 对交互式工作流有价值
- 可以在 ACP router 或 team-lead skill 中使用

#### 9. Fast Memory Recall
- 已经自动生效的优化，不需要特别行动，但可以观察 memory_search 响应时间变化
