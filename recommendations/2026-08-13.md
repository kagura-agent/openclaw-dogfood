# 采用建议 — 2026-08-13

## 1. 为 model-call 超时风险配置 job 级 fallback 与 timeout 边界
**优先级：高｜风险：低（先只读盘点 run history，再单点试点）**

- **能力：**cron `agentTurn` payload 支持 `model`、`fallbacks`（模型回退列表）与 `timeoutSeconds`；job 级 `failureAlert` 可对连续失败告警。
- **场景：**今日 03:15 `daily-review` 以 `model-call-started` 超时（deepseek-v4-pro/floway-sg-deepseek 1800s 无首 token），夜间 3/4 核心 job 同段超时——这是「模型后端无首 token」而非任务逻辑错误，与 08-12 记录的 8 个 error-status 是不同故障面。
- **建议：**先读取 `daily-review` / `nightly-backup` / `critical-cron-watchdog` 的 run history 与 last error，确认是否同一时段/同一 provider。对确认受模型后端影响的 job，试点加 `fallbacks`（如 floway-sg 主 + 备选）与合理 `timeoutSeconds`，并仅给尚无可靠提醒的关键任务配 `failureAlert`（连续 2 次失败再告警）。不自动重跑、不改外部写权限。
- **验收：**一次 model-call 超时能被分类为「provider 无首 token」并自动回退/告警，而不是静默归入 error status。
- **收益：**把「3/4 核心 job 夜间超时」转化为可处理的分层告警，避免每日审计时才发现。

## 2. 把 memory_search 降级路径固化为 Standing Order
**优先级：中｜风险：低（只改 prompt/流程说明，不动 runtime）**

- **能力：**`memory_get` 定点读取 + `memory_search` 语义检索的组合，可在检索 provider 不可用时给出确定性降级。
- **场景：**memory_search 已连续多日 embedding/provider error；当前降级路径（已知文件→`memory_get`，未知→直读 daily/权威源）在 channel-patrol / daily-review / dogfood 中口头沿用，但未沉淀为可执行规则。
- **建议：**把「检索不可用时的降级顺序」写成一条短 Standing Order（已知日期/实体先 `memory_get` 当日文件；仅未知位置才 `memory_search`，且输出需带日期/路径并把模糊命中标为待核验），供所有依赖记忆的 cron 复用。
- **验收：**任一 cron 在 memory_search 不可用时不再产出「无结论」或命中陈旧 dreaming 文本的结论。
- **收益：**以最小变更消除记忆污染，同时为日后 runtime 级 provenance 改进保留可比较基线。

## 3. 结构性修复 spam-filter 输入契约（工具债）
**优先级：中｜风险：低（独立脚本改动，可本地测试）**

- **能力/场景：**spam-filter.sh 只接受 raw GitHub API JSON，study/patrol 多次误用 `gh api --jq` 预格式化 TSV 输入（今日为第 4 次复发），每次都空跑重试。
- **建议：**让 spam-filter.sh auto-detect 输入形态（JSON / TSV / `--jq` 预格式化），拒绝时给出明确报错而非静默空输出。
- **验收：**同一条错误输入不再产生静默空结果；复发计数归零。
- **收益：**消除重复摩擦，比继续加行为提醒成本更低。

## 暂不采用
- **暂不升级 `2026.7.1-2`。**唯一变更仍是 npm 插件 metadata 兼容性，无新功能；维持维护窗口受控升级。
- **暂不自动重跑超时的核心 cron。**先按 run history 区分 model-call 超时与逻辑失败，避免盲目补跑放大 provider 压力。
