# 采用建议 — 2026-08-07

## 1. 将 `2026.7.1-2` 纳入下一次官方插件变更的升级窗口
**优先级：中｜风险：低（升级本身仍会影响运行时）**

- **能力**：该 correction release 修复了新版 npm 以 singleton-array metadata 返回官方插件信息时的安装/更新兼容性。
- **场景**：我们使用多个 OpenClaw plugin skills；过去已有插件兼容性摩擦，而下一次受跟踪官方插件更新可能触发该路径。
- **建议**：不为当前没有复现的失败紧急升级；在下一次需要安装/更新受跟踪官方插件前，升级到 `2026.7.1-2` 或更高稳定版。
- **验收**：核验版本；运行 `openclaw doctor`；进行非破坏性插件查询/更新预演；确认 plugin skill discovery 与一个 Discord cron delivery 正常。
- **收益**：以一次受控维护避免 npm metadata 格式变化导致插件更新中断。

## 2. 只在 job 所有者上下文试用 cron `runs` 诊断
**优先级：高｜风险：低**

- **能力**：cron 管理支持按 job 查询 `runs`；但当前 isolated run 的权限只暴露本 job，因此不能把 `list` 的局部结果当作全局 scheduler 状态。
- **场景**：Cove/ABTI/OpenCode 等巡检曾报告 403、超时和 cancelled job，需要原始执行与 delivery 记录才可判定是否重试、改 payload 或降频。
- **建议**：由持有目标 job 上下文的频道/主 session 先读取一个非关键失败 job 的最近 run history，仅归档证据，不重跑或改配置。
- **验收**：能清楚区分执行失败、delivery 失败、timeout 和 skipped，并在结论中标注查询范围。
- **收益**：减少从频道摘要或局部权限视图推断全局故障的风险。

## 暂不采用
- **没有新增功能可立即试用。**v2026.7.1-2 的 release body 只有上述一个 npm plugin 修复；不为凑 adoption 项目而改 cron、模型或线程策略。
