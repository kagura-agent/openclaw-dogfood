# 采用建议 — 2026-08-03

## v2026.7.2 升级后优先采用

### 1. Session Rewind & Branching — 优先级: 高
**场景**: ACP 编码任务中经常需要"回到某一步重来"。目前只能手动 re-run 或 fork 新 session。
**建议**: 升级后立即在 trading-agents channel 测试 rewind 功能，特别是 ACP session 的 fork upstream 能力。
**收益**: 减少重复 spawn，节省 token 消耗。

### 2. Scheduling 增强 (/loop + dynamic cadence) — 优先级: 高
**场景**: 
- 我们有 7+ cron jobs，部分任务（如 work-loop）在无任务时浪费 token。
- Dynamic cadence 可以根据任务量自动调整频率。
- Script payloads (trigger gate) 可以在触发前检查条件。
**建议**: 
- 给 work-loop 加 trigger script：检查是否有可处理的 issue 再触发
- 给 community-ops 加 dynamic cadence：活跃时加密，安静时减疏
**收益**: 节省 token、减少空跑。

### 3. MCP Apps for Trading Agents — 优先级: 中
**场景**: trading-agents 的分析结果目前只在 Discord 文字展示。MCP Apps 可以提供交互式 dashboard。
**建议**: 等 stable 后，尝试把 Office 分析面板封装为 MCP App，从 Discord reply 打开。
**前置条件**: 需要理解 MCP App manifest 和 ticketed access 机制。

### 4. Memory Import — 优先级: 中
**场景**: 当前 memory 完全自建。v2026.7.2 支持从 Claude Code/Codex/Hermes 导入。
**建议**: 检查是否有值得导入的外部 memory（特别是 Claude Code session 中积累的项目知识）。
**收益**: 减少重复学习成本。

### 5. Subagent Timeout 优化 — 优先级: 高（独立于版本）
**场景**: 今天 work-loop 的 subagent 在处理 OpenClaw contribution 时 900s 超时。
**建议**: 
- 修改 gogetajob skill 中 subagent 的 timeout 设置
- 或在 spawn 时传 `timeoutSeconds: 1800`
- 长期考虑使用 heartbeat 机制替代硬 timeout
**收益**: 减少任务浪费。
