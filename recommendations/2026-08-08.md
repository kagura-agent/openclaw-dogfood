# 采用建议 — 2026-08-08

## 1. 小范围试用只读 `openclaw audit` 做跨频道 cron 复盘
**优先级：高｜风险：低（只读 metadata 查询）**

- **能力**：`openclaw audit` 可按时间、agent、session、run、状态及 `agent_run`/`tool_action` 类型查询 bounded 的 metadata-only 记录；支持 JSON 分页。
- **场景**：当前 isolated cron 对其他 channel scheduler 的可见性不足，`cron list` 曾超时；频道摘要能说明结果，却不足以区分执行、工具调用、delivery 或 timeout 的原始边界。
- **建议**：在拥有目标 job/agent 可见性的受控 run，先对一个已知的非关键 cron 做只读实验：`openclaw audit --after <ISO> --kind tool_action --json --limit 50`。只保存脱敏后的字段、命令与结论，不重跑、不变更 scheduler。
- **验收**：确认记录含足以关联 session/run、时间、工具动作及终态的 metadata；并确认不会暴露 prompt、凭据或频道内容。若没有目标 job 记录，明确记录权限/覆盖范围，而非猜测。
- **收益**：为 recurring-cron failure triage 增加原生可审计证据，减少从 daily 摘要或局部 cron 视图推断全局状态。

## 2. 在下一次插件维护窗口升级到 `2026.7.1-2`
**优先级：中｜风险：低（升级本身仍会影响运行时）**

- **能力**：该 correction release 兼容新版 npm 的 singleton-array metadata，使受跟踪官方插件能安装/更新。
- **场景**：我们使用 plugin skills，且这个兼容修复正好覆盖未来官方插件更新的潜在阻塞路径。
- **建议**：不为今天未复现的失败紧急打断 cron；在下一次需要更新官方插件时，升级至 `2026.7.1-2` 或更高稳定版。
- **验收**：核验版本；运行 `openclaw doctor`；做非破坏性插件查询/更新预演；确认 plugin skill discovery 与一条 Discord cron delivery 正常。

## 暂不采用
- **不因 audit 可用就扩大审计采集。**先验证 metadata 覆盖、权限边界和脱敏输出；不采集或外发内容、prompt、凭据，也不据单一 job 结果宣称全局 scheduler 健康。
- **不为单一插件 hotfix 立即升级。**当前没有官方插件更新失败的直接证据，维持稳定运行优先。
