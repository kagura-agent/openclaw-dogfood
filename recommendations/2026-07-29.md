# 采用建议 — 2026-07-29

## 基于 v2026.7.2-beta.5 的采用计划

### 🟢 立即采用（stable 发布后第一天）

#### 1. CJK Compaction 修复
- **场景**: 我们 90%+ 对话为中文，compaction 估算不准直接影响上下文管理
- **动作**: 升级后无需配置，自动生效
- **验证**: 观察长对话的 compaction 时机是否更合理

#### 2. Cron Reliability 改进
- **场景**: 12+ cron jobs 全天运行，重启后偶有漏执行
- **动作**: 升级后自动生效（one-shot catch-up + state preservation）
- **验证**: 下次 gateway restart 后检查所有 cron job 是否正常恢复

#### 3. Discord Delivery Durability
- **场景**: 我们主要在 Discord 交互，crash 时偶尔丢消息
- **动作**: 升级后自动生效
- **验证**: 模拟 gateway restart 后检查消息完整性

### 🟡 短期采用（stable 发布后一周内）

#### 4. Session Rewind & Branching
- **场景**: 长对话探索不同方案时，经常需要回到某个节点重试
- **动作**: 需要在 web UI 或 native app 中使用 rewind/fork 功能
- **评估**: 是否能替代我们当前的 "新开 session 重来" 模式

#### 5. Per-job Dynamic Cadence
- **场景**: version-check cron 在无新版本时可以降频，有发布时加频
- **动作**: 给 version-check job 添加 trigger script，检测到新版本时缩短检查间隔
- **评估**: 先在一个 job 上试验

#### 6. Fast Active-memory Recall
- **场景**: memory_search 每天使用频繁，跨对话记忆很重要
- **动作**: 确认个人安装默认启用后，观察 recall 速度和准确性变化
- **验证**: 对比升级前后 memory_search 的响应时间和相关性

### 🔵 中期评估（两周+）

#### 7. Claude Opus 5 模型切换
- **前置**: 等社区反馈稳定性和性价比
- **场景**: 复杂推理任务（code review, spec review, 多 agent 协调）
- **评估标准**: 响应质量 vs 成本 vs 延迟

#### 8. Interactive MCP Apps
- **前置**: 设计一个具体 MCP App 场景（如 PR dashboard、issue tracker）
- **场景**: 在 Discord channel 中直接操作结构化数据
- **评估标准**: 是否比当前 text-based 交互更高效

#### 9. `/loop` 命令
- **前置**: 理解与现有 cron 的区别和适用场景
- **场景**: 临时性重复任务（如连续监控某个 CI 状态）
- **评估标准**: 是否比手动重复触发更方便

## 不采用

- **Wear OS companion**: 无硬件
- **Meetings plugins**: 当前无会议集成需求
- **Local inference (llama.cpp)**: 我们用 cloud providers，本地推理不适用
